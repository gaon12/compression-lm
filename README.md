# compression-lm

Text generation and comparative analysis using **general-purpose compressors
as language models**. No neural network, no training, no parameters beyond
the corpus itself: a continuation that compresses well against a primed
context is, by definition, predictable under it — so compressed length is an
implicit conditional probability.

Inspired by the idea behind `gzipt`; this is an independent implementation
built around a pluggable backend registry so many compression algorithms can
be compared side by side.

```text
$ clm generate --corpus data/tiny_shakespeare.txt --backend deflate \
      --prompt "KING:" --length 160 --temperature 0.8 --seed 3 --corpus-gate

KING:
 thence I have follow'd it,
Or it howl'd away twelve winters.

ARIEL:
Pardon, masters
And in her most lying slave,
Whom
```

## Install

```bash
pip install -e .          # stdlib backends only (deflate/gzip/zlib/bzip2/xz/lzma/lzma2)
pip install -e ".[all]"   # + zstd, brotli, lz4, snappy
pip install -e ".[dev]"   # + pytest, ruff
python scripts/fetch_data.py   # fetch the tiny_shakespeare corpus (if absent)
```

`lzo` exists as a backend (`pip install python-lzo`) but ships no Windows
wheels — the registry marks unavailable backends instead of failing.

## Usage

```bash
clm backends                                    # list backends + availability
clm generate --corpus data/tiny_shakespeare.txt --backend zstd \
    --prompt "MENENIUS:" --length 200 --temperature 0.8 --stats
clm compare --corpus data/tiny_shakespeare.txt --prompt "KING:" \
    --length 120 --corpus-gate --out reports/   # every backend, one table
```

Search knobs (both `generate` and `compare`):

| flag | default | meaning |
|---|---|---|
| `--beam-width` | per speed class | partial hypotheses kept per depth |
| `--lookahead` | per speed class | span depth planned then committed |
| `--temperature` | 0.0 | 0 = argmin span; >0 samples `exp(-(s-best)/T)` |
| `--context-bytes` | backend limit | corpus tail primed into the context |
| `--memory` | 128 | generated bytes visible to the scorer |
| `--tiebreak` | corpus | `corpus` prefers verbatim continuations on length ties |
| `--corpus-gate` | off | only score candidates occurring in the context |
| `--repeat-penalty` | 0.0 | extra bytes charged per reused n-gram |
| `--workers` | 1 | threads for candidate scoring |
| `--seed` | random | RNG seed |
| `--opt K=V` | — | backend option (e.g. `--opt level=9`, `--opt preset=1`) |

## How it works

**Scoring.** `measure(candidate) ≈ len(compress(context + candidate)) −
len(compress(context))` — the extra bytes a context-primed compressor spends
on the candidate, a `-log P`-style conditional code length. Three backend
strategies compute it:

- **encoder-state cloning** (deflate/gzip/zlib): the context is compressed
  once into a `compressobj`; each candidate is measured on an independent
  copy of the live encoder — O(candidate) per call.
- **dictionary priming** (zstd, brotli, lz4): the context is attached as
  match history (raw-content dict / `dict=` arg); candidates compress alone.
- **one-shot fallback** (bzip2, lzma family, snappy, lzo): full
  `context + candidate` recompression per candidate — correct but
  O(context), so these backends cap their context size.

**Search.** Each round beam-searches `lookahead` bytes deep over the corpus
alphabet (byte values seen in the corpus — ~3x fewer branches) and commits
the winning span. The context is the corpus tail plus the last `memory`
bytes of output, which both primes the compressor and hides older output
so it can't score by copying itself.

**Byte-granular ties.** Compressed lengths are whole bytes, so dozens of
candidates tie at the minimum every depth. `--tiebreak corpus` (default)
prefers candidates still occurring verbatim in the context — on a periodic
corpus this takes greedy output from ~0% to ~100% corpus 8-grams.
`--corpus-gate` goes further and only *scores* in-context candidates:
~20x fewer compressions, output becomes strict corpus recombination.

## Observed behavior (tiny_shakespeare, `KING:`, 120 B, gate on)

From a real `clm compare` run — illustrative, not a benchmark:

- `deflate`/`gzip`/`zlib` (same algorithm, different framing): identical
  outputs, ~94% corpus 8-gram overlap, most coherent text.
- `snappy`: highest copy ratio (~94%) at near-zero reported cost — no
  entropy coder means matches dominate the score.
- `lz4`, `zstd`, `brotli` (dictionary priming): coherent recombination,
  slightly lower corpus overlap than window priming.
- `bzip2` (BWT, no match window) and the `lzma` family (4 KiB contexts):
  visibly more fractured output; lzma variants are ~5-10x slower per byte.
- `lzo`: skipped — package unavailable on this platform.

`bits/byte` is the model's mean self-reported conditional code length:
comparable *within* a scorer, not across scorer types (dictionary and
concatenation scoring have different overhead baselines). `copy%` is
8-gram corpus overlap; `self-rep%` catches degenerate looping.

## Second-phase benchmark

A rigorous, resumable benchmark separating three questions:

1. **Prediction** — teacher-forced next-byte scoring on held-out test
   positions (all 256 candidates per position, average-rank + expected
   top-k under random tie-breaking, pseudo-BPB).
2. **Equal-search generation** — identical beam/lookahead/temperature/
   prompts/context for every backend.
3. **Equal-compute generation** — identical candidate-evaluation budget
   per output byte; lookahead tuned on *validation* only.

```bash
python benchmark.py --dataset data/tiny_shakespeare.txt --mode quick   # ~1h
python benchmark.py --dataset data/tiny_shakespeare.txt --mode full    # ~3h
python benchmark.py --mode quick --backends deflate,zstd --positions 200
python benchmark.py --assemble-only   # rebuild CSVs/plots/report from raw rows
```

Data splits: contiguous train/val/test ranges (80/10/~10%) with 4 KiB
discarded boundary gaps — only train primes compressors, only validation
tunes hyperparameters, only test positions are scored. Seed 42.

Key flags: `--positions`, `--contexts`, `--budgets`, `--prompts`,
`--workers`, `--seed`, `--skip teacher,generation,overhead,speed`.

Outputs under `results/`: `summary.csv`, `teacher_forced.csv`,
`generation_equal_search.csv`, `generation_equal_compute.csv`,
`copy_metrics.csv`, `speed.csv`, `quantization.csv`, `overhead.csv`,
`backend_status.csv`, `generations/`, `plots/`, `config.json`,
`report.md`, `raw/` (checkpoints — re-running resumes where it stopped).

Reading the results: **`teacher_forced_pseudo_bpb`** is the held-out
next-byte metric; **`generated_compression_bpb`** only measures how
compressible a model's *own* output is — a backend that copies the corpus
verbatim scores a *lower* gen-BPB. They are never interchangeable; see
`copy_metrics.csv` for the retrieval/copy analysis.

## Third-phase benchmark

`benchmark_v3.py` checks the second-phase findings with identical effective
contexts, multiple zstd scoring modes, multi-byte discrimination, equal-time
generation, and a second dataset (WikiText-2). Its detailed output is
`results_v3/report.md`; `results_v3/summary.csv` pairs 4 KiB teacher-forced
scores with generation statistics from the highest equal-evaluation budget.

```bash
python benchmark_v3.py --dataset tiny_shakespeare --out results_v3
python benchmark_v3.py --dataset wikitext2 --out results_v3 --resume
python benchmark_v3.py --assemble-only --out results_v3
```

Resume accepts additional phases or backends for the same dataset and run
settings. It rejects changed data or settings in an existing output directory;
use a new `--out` path for a different experiment. Failed tasks are retried.
The benchmark report's pseudo-BPB is not a calibrated language-model metric.
